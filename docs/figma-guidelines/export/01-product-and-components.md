# Men of Hunger: product and components

The screen should feel as simple as Apple and work as efficiently as Linear.
Make its primary job clear immediately. Keep useful information, permissions,
accessible interactions, and existing states when revising a design.

Use the components, variants, vector icons, typography, and variables in
Men of Hunger — UI Library. Edit shared masters when improving a reusable pattern;
keep instances attached. Inspect the nearest existing implementation before
introducing a new component. A partial mockup does not authorize removing behavior.

Dense feeds, member lists, notifications, and settings use full-width rows with
quiet dividers. Metadata earns its space. The page is the content surface; do not
wrap an entire route in a card. Use one obvious primary action and put secondary
actions in a menu or a deeper view when that preserves discoverability.

Design loading, empty, error, selected, disabled, and permission-dependent states.
Prefer skeletons for content loading and specific empty copy that offers the next
useful action. Use short labels such as Post, Save, or Check in. Correctness,
privacy, and accessibility take priority over visual minimalism.

Avoid cards inside cards, decorative badges on every row, KPI tile dashboards,
ambiguous icon-only actions, gratuitous gradients, confetti, and bro-app chrome.
Do not remove useful content solely to achieve a minimal appearance.
